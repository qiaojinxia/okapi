## 官方契约

- 代码执行官方提供 `usage.server_tool_use.code_execution_requests`，但额外费用按
  容器执行时长计算，有最短时长、组织免费额度及新版搜索/读取组合免收规则。
  次数不是小时数；普通函数或响应结果块不是原生计数证据。
  [代码执行工具](https://platform.claude.com/docs/en/agents-and-tools/tool-use/code-execution-tool)
  2026-10-01 同时归档网页 Reader 与官方 `.md` 原始源码，后者保留 usage 示例。
  本阶段已验证执行次数保留、明确声明或非零观察的不完整成本覆盖标记。
  不发布未核实的容器单价，不根据 count 推算时长；范围见本文件末尾接受记录。

- Anthropic 搜索使用 `usage.server_tool_use.web_search_requests`，每千次搜索 $10，
  内容 Token 另计；搜索错误不另收搜索费，结果数不是次数。动态过滤可隐藏结果块，
  应采用 usage 计数。[搜索工具](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool)
- `web_fetch_requests` 是另一计数轴，网页读取没有额外工具费，内容仍收 Token 费。
  [网页读取工具](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-fetch-tool)
- Messages 流式使用累计用量快照；实现按轴保留缺省、覆盖最新值，并拒绝计数倒退。
  不把重复事件、结果条数、普通客户端工具名当作额外调用。
  [流式协议](https://platform.claude.com/docs/en/build-with-claude/streaming)
- OpenAI web_search 当前每千次 $10；搜索动作收费，`open_page` / `find_in_page`
  不能按搜索动作重复计费。file_search 为每千次 $2.50，限 Responses；存储按 GB-day，
  容器按资源/会话或时间。旧 preview 工具与模型有不同价格，不能一个默认值覆盖。
  [价格](https://developers.openai.com/api/docs/pricing)、
  [搜索动作](https://developers.openai.com/api/docs/guides/tools-web-search)

## 独立价格与费用明细（选定阶段已验收）

工具费配置绑定原生用量契约，并随模型草稿显式发布。示例请求字段为：

```json
{
  "server_tool_prices": {
    "usage_contract": "anthropic_server_tool_use_v1",
    "web_search": {"billing": "additional", "price_per_request_micro": 10000},
    "web_fetch": {"billing": "included"}
  }
}
```

`additional` 单价为非负整数 micro/request，明确 0 免费；`included` 表示费用已包含，
不允许夹带单价。两轴须齐全，拒绝额外字段、错误契约、负数、字符串单价及非整数。
草稿省略字段保留已有配置，空对象清除；重载和公开价格 API 只读发布快照，旧 epoch
不从代码获取新默认价。无配置的旧模型保持原收费，明细的未知单价/费用不是免费。

每个已观察工具独立保存数量、策略、单价、list/original/amount/discount；费用在
micro·scale 沿分组、个人、选中规则逐步 floor，再与原 Token 分量 checked_add。
模型倍率、Token 阶梯、service_tier 和缓存倍率不会重复作用于工具费。原 Token
舍入不变；每工具分量最终单独 floor，不能先合并后取整。PG/outbox/CH 沿既有四
金额列保存合计，退款使用已结算合计，不按当前工具价重算。

用量契约版本不等于工具实现版本，不能从原生计数反推出具体工具修订版或资源时间。
配置了非零额外价但部分观察缺少该轴时，结算拒绝并退款。完全没有工具观察的普通
报价仍兼容旧行为；请求声明绑定、工具预扣上界和完全缺省用量的完整性检查仍需补齐。
无价格的非零/未知工具用量使完整成本未知；估算成本溢出也保留未知，不用最大整数
充当已知金额。渠道系数仍是站内估算来源，不能用它证明真实厂商账单齐全。

当前实际失败分别保留：费用 v2 完整财务执行退出 101（200 通过、1 失败），检出

## 请求准入与工具上限（选定阶段已验收）

2026-10-01：明确的 Anthropic 搜索/读取原生 `type` + `name` 才建立工具授权，
普通函数同名不算。支持的工具定义及其选项在四个 HTTP 入口转换后保留；原生声明
只选 Anthropic 方言渠道。`max_uses` 缺省显式补 5，属于站内策略，不是厂商默认；

`web_search_preview` 等原生类型保持原请求，不会被误认成 Anthropic 日期工具。

Token/TPM。此策略比较保守：更贵的可配置降级会提高预扣，即使主模型最后可用。

Token 分量、工具费用与合计。候选工具数量是声明上限，不能作为上游实际观察。
预扣取最大候选金额的原策略保持不变，未知价格仍为 null。失败记录只存 epoch 和
