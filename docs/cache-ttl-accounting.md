# 缓存 TTL 实际接口核对

本项验证已实现的计费设计，没有修改价格公式。之前的 `cache_ttl` 价格单测不能代替实际网关、协议转换、结算和统计验证。

## 输入与费用依据

模拟 Anthropic 上游报告常规输入 100、缓存读取 800、缓存写入 100、输出 50、思考输出 20。缓存写入由 5 分钟的 60 和 1 小时的 40 组成。归一化输入为 1,000，总 Token 为 1,050；思考输出属于输出的细分，不再次累加。

价格使用真实发布后的 PriceBook：基础价格每百万 Token 2,000,000 micro-USD，输入倍率 1、输出倍率 2、缓存读倍率 0.5、通用缓存写倍率 1.25。TTL 倍率相对于普通文本输入价；替换该 TTL 的通用写入费用，不叠加。

| 场景 | 5 分钟倍率 | 1 小时倍率 | 预期扣费 micro-USD | TTL 用量状态 |
| --- | --- | --- | ---: | --- |
| 两档独立价格 | 1.25 | 2 | 1,510 | 60 / 40，1 个样本 |
| 上游未提供 TTL 细分 | 1.25 | 2 | 1,450 | 未知 / 未知，0 个样本 |
| 没有 TTL 价格覆盖 | 通用 1.25 | 通用 1.25 | 1,450 | 60 / 40，1 个样本 |
| 两档价格明确为零 | 0 | 0 | 1,200 | 60 / 40，1 个样本 |
| 仅覆盖 1 小时价格 | 通用 1.25 | 2 | 1,510 | 60 / 40，1 个样本 |
| 细分和总量矛盾 | 60 + 41 ≠ 100 | 不计价 | 0，释放预扣 | 返回上游用量错误 |

两档独立价格的费用是：常规输入 200 + 缓存读取 800 + 5 分钟写入 150 + 1 小时写入 160 + 输出 200 = 1,510 micro-USD。

## 实际调用与断言

六个场景分别经 `/v1/messages`、`/v1/chat/completions`、`/v1/responses`、Gemini `generateContent` / `streamGenerateContent` 入口调用，每个入口同时验证 JSON 和 SSE，共 48 个新调用组合。所有这些调用的上游均为 Anthropic 模拟服务，不能据此证明原生 Gemini 或其他厂商有相同 TTL 含义。

成功场景验证：钱包余额、PG 余额变化、API key 累计费用、唯一账单、价格 epoch 和实际费率快照、PG 到 outbox 到 CH 的四金额及缓存计数、用户日志汇总、用户看板调用数/Token/费用/缓存命中率。思考输出不增加总 Token，缓存命中率是 800 / 1,000 = 80%。没有 TTL 细分时保留未知，不补造零或拆分。

SSE 包含局部用量、累计终值、重复终值和缺少用量的尾帧。重复终值不能重复收费。错误场景的 SSE 后续再报告合法值也不能恢复计费；JSON 返回 502，已开始的 SSE 返回错误事件，余额不变、凭证费用为零、只调用上游一次并仅生成一条结算记录。

测试实现位于 `bins/okapi/tests/support/cache_ttl_billing.rs`，复用真实发布边界，在发布及 gateway 启动前配置费率，没有直接向进程塞入自制 PriceBook，也没有手工写入统计记录。
