# Token 来源与部分用量

2026-09-28，进行中。原有估算结果与上游实报没有来源区分；部分协议探针还把缺失的总计数补成零。

结算的 `TokenUsage.upstream_usage` 保存原始输入、输出总计数（OpenAI 口径，输入含缓存，输出含推理）。外层缺失表示旧数据或来源未记录，不能推断为实报；对象存在但某轴为 null 表示该轴缺失并使用本地估算。原始计数等于结算数为 `upstream`，不等为 `local_override`；缺失轴为 `estimated`，无来源对象为 `unknown`。本地复核只允许提高总量，保留原数以供核对。

部分用量保留已提供的计数和缓存细分，仅估算缺失轴；明确零仍是零。估算至少覆盖已知子项。总数加另一轴能唯一确定缺失轴时，使用上游总数推导；类型错误、负数、越界或矛盾不能转入估算路径。Anthropic message_start 的输出是暂定值，没有后续输出时保留已知输入/缓存并估算输出，不把开始时的输出当作最终值。

来源随 PG `usage_details.tokens`、结算回执、outbox 和 CH 明细保留。CH 新列默认 `unknown`/NULL，禁止回填猜测历史来源。管理及个人日志暴露同一份来源信息。本阶段之后还需验证长周期聚合中的来源覆盖、图片/音频/Realtime 等专用路径及真实供应商账单。

现有看板继续按结算 Token 汇总，因此其中可能包含估算或本地修正；本阶段没有把看板所有总量和比率改成“仅上游实报”的口径，也未增加聚合中的来源占比。后续必须给聚合查询补上来源覆盖与估算占比，尤其不能仅凭缓存计数已上报，就将采用估算输入作为分母的命中率解释为供应商实测命中率。

流式快照按轴替换，绝不把累计值相加。后一份缺少某轴时沿用先前已知值与子项；字段明确出现则采用新值。gateway 的正常泵送、终态缓冲和断连收尾，以及 Chat 转 Messages/Responses/Gemini 的状态机均保留这些信息。任何一份非法用量都会使该请求后续用量保持非法，不能由“最后一份看起来合法”恢复收费。Anthropic 缓存越界不再被转换器截断成一份合法外观的 usage，结算仍拒绝。

这里只将总数和另一轴唯一推出的计数视为上游计数，不进行主观拆分。缺失输入的本地估算至少覆盖已知缓存及模态计数，仍是估算，不能代替供应商账单。未扩展细分字段的采集标记，也未给未知来源的历史数据制造标记。
