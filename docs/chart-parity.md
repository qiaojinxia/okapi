## 数据口径

- **总 Token = 输入 + 输出**。缓存读取／写入属于输入，推理属于输出，不能重复相加。
- 标价消费使用实际消费与优惠之和；金额从整数 micro-USD 换算展示，CSV 保留当前图表原始数值及单位。
- 平均耗时为总耗时／请求样本数；TTFT 为有首字时间的样本加权平均，不能平均每日平均值。若门户附加聚合的样本覆盖不完整，对应指标返回 `null`。
- 输出速度为输出 Token／请求总耗时，**包括首字等待**，并非纯生成阶段速度；界面显示 `Token/s`，与 RPM／TPM 口径不同。
- 无请求日的计数与消费为 0；无分母的命中率、成功率和无性能样本的点为未知，折线不跨越这些空点。
- 门户、管理分析与首页总览的“近 7 天”含今天共七个日历日；日期包含首尾，按服务端时区统计。管理分析的上一期是紧邻当前范围、同样日历天数的窗口；包含今天时，本期尚未走完，不是等时刻比较。
- `generated_at` 是查询时间。管理端另有全站 `last_event_at`、`last_ingested_at`、待入库／失败数、积压时长与延迟状态；空闲不会因“很久没请求”而误报延迟。最大事件时间是全站观测信号，不是所有历史事件均已消费的严格水位。
- 新增物化视图只捕获创建后的数据。历史未采集的缓存写入无法恢复；缺失信息不回填成 0。部署说明见 [数据库设计](database.md#32-mv-矩阵aggregatingmergetree)。

## 本轮补齐的分析维度

| 能力 | 实际实现 |
| --- | --- |
| 请求／计费／上游模型 | 网关结算与 outbox 分别保存原始请求模型、计费模型和发给上游的模型；可切换模型口径、按模型筛选／拆分／比较。真实网关别名与渠道映射测试验证三者没有混淆。 |
| 请求／上游端点 | 保存规范化路径模板，覆盖 Chat、Messages、Responses、Gemini、Embeddings、Rerank、音视频、Realtime；自定义透传使用路径模板，不把完整 URL、查询参数或任意请求正文作为维度。 |
| 调用与计价方式 | `stream`、`non_stream`、`websocket` 调用类型与流式条件；`billing_type` 表示 Okapi 计价快照的 `ratio`／`tiered`／`per_call`，不是上游产品的订阅扣费来源。 |
| 自选日期与组合筛选 | 日期、粒度、模型口径、节点、双向端点、调用与计价方式共用一套查询条件；模型／分组各最多八项，组内 OR、组间 AND；应用后才查询，管理分析条件存入 URL，刷新和跨视图保留。 |
| 模型 × 分组性能比较 | 请求、消费、Token 可堆叠；错误率、缓存命中率、平均耗时、TTFT、吞吐使用独立折线。Top N 的“其他”先合并分子／分母再计算比率和平均值。无样本点留空。 |
| 节点流向与阶段配置 | 用户→网关节点→密钥→分组→模型→渠道；可选至少两个阶段及每阶段 Top 3／6／10／20。隐藏阶段从同一调用组合重新汇总，保持相邻路径守恒。 |
| 成本覆盖率 | 已知成本包含零成本；仅完整覆盖时返回全量毛利，否则 `margin_micro=null`，单独返回已采集记录的收入、成本及毛利。首页、分析、拆分与经营报表统一口径。 |
| 真实入库状态 | 显示全站最近事件、最近入库、积压与失败，而不是把页面查询时刻写成数据更新时间。 |

### 保留历史的升级方式

新增 `mv_analysis_hour`，不改写旧 `mv_cube_hour`。查询将新聚合与旧立方体中未被新聚合覆盖的部分合并，旧键上的请求、费用和 Token 不重复计算。旧记录没有的新维度保留为“未采集”，不会假设它们属于当前模型映射或请求端点；未知维度不能用于精确下钻。成本和缓存写入按已知样本标记覆盖率。无需扫描原始日志或回填旧聚合。

### 对标边界

这里补齐的是上轮明确列出的分析缺口，不能据此宣布全产品超越。多维性能比较使用加权平均，分位数仍在原有模型／渠道质量表中；成本按官方价 × 渠道成本系数估算，并非供应商账单核销成本；自定义透传未解析的模型、无法确认上游的失败和旧数据仍会归入未知维度；Chat、Embeddings／Rerank 在已发起上游调用后的失败保留最后尝试的上游模型和端点。全站入库状态也不是每个筛选组合的独立消费水位。对比任一产品的订阅、供应商结算等其他功能，需要单独验收其业务语义。
