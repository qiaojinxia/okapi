# 缓存写入聚合与旧残差核对

2026-09-29，本阶段实现与回归已完成；整体核心验证仍进行中。修正完整范围有三笔各 100 写入、新分析视图只含最后一笔时错误返回写入 100、采集数 3 的问题。数量与采集数必须来自同一记录范围；主输入/输出、价格、四金额和扣款公式不变。

新增独立无 TTL 的 `mv_cache_totals_5min`，完整维度与模态/来源五分钟视图一致，记录所有请求数、保存的写入总数及明确读取/写入样本数。写入样本还须有数字，明确零有效。新 MV、raw 与旧日聚合互相覆盖，择一使用，不能拼加。

旧日聚合只在能够证明完整父粒度属于唯一当前子粒度时用于恢复：原立方体确认父级全部请求，恢复写入要求旧 `mv_cache_write_day` 的非空数字覆盖全部父请求；读取采集数独立保留，读写采集数均不得超出请求数，映射到子粒度没有第二个可能目标。跨小时、渠道或分组无法唯一分配时不得猜分配；全范围总计另按自身完整粒度恢复，使完整日总数可用而小时子项诚实返回 null。原始明细完整时优先使用 raw。

现代部分的写入和/样本来自自己的完整缓存记录，或由同父级全部请求均明确上报而证明其子集全部上报。历史残差只在父级和现代部分可正确相减时派生，禁止把旧采集数直接贴到只有新数量的行上。无法分配的历史保留主请求、费用和 Token，总写入或细分返回 null，不能降低采集数来伪装修复。

管理趋势总计/上一窗口、拆分及 provider/其他折叠、流向总指标，个人用量/年度活动均遵守同一范围；明确零、未采集、非法聚合、缺口和时间/用户/密钥/模型/渠道隔离需实际回归。保留首轮失败和源指纹，不把模拟数据当作真实供应商对账。

严格 Clippy 首轮发现函数长度告警，按查询生成、缓存指标封装与测试夹具拆分；没有禁用 lint。最终结果与源码边界见下，目标整体仍为进行中。

## 未完成边界

TTS 当前仍将字符数放入 `prompt_tokens`（`gateway/audio.rs`），并用于准入估算和结算统计；Token 与字符单位尚未分开，不能据此声称总 Token 与实际供应商 Token 始终相等。两种缓存 TTL 独立价格、工具调用独立费用、真实供应商账单核销及完整竞品核心能力/API 生命周期对齐仍需后续核对。旧日写入量缺少可唯一分配信息时，无法重建小时、渠道或高级维度的精确分布；本阶段不推算这类值，保留原主请求/Token/金额。
