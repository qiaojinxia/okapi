## 指标口径

| 指标 | 计算方式与边界 |
| --- | --- |
| 输入 `prompt_tokens` | 已包含缓存读取和缓存写入；音频、图片也是输入内部的细分。Anthropic 的普通输入、缓存读、缓存写先归一到同一个输入总数。 |
| 输出 `completion_tokens` | 已包含推理、音频和图片输出。推理 Token 是输出子集，不能额外加到总量。 |
| 总量 `tokens` | 输入 + 输出。缓存与推理只做拆分，不重复相加。 |
| 音频/图片输入细分 | 保存的 `audio_prompt_tokens` / `image_prompt_tokens` 是扣除缓存读写交集后的输入段；完整模态输入还需加上对应的缓存模态读写段。它们及交集均已包含在输入总数内，不能额外加到 `tokens`。新观察对象区分完整、部分采集和历史未知。 |
| Token 来源 | 单笔输入、输出分别为 `upstream`、`estimated`、`local_override` 或 `unknown`。原始上游计数保存在 `upstream_usage`；当前聚合总量是结算口径，可能包含估算和复核值，聚合已附来源覆盖及请求、Token 占比。 |
| 缓存命中率 `cache_hit_bp` | 总缓存读取 / 同批上游实报且未本地修改的输入 × 10,000；全部请求都满足且分母大于零才返回，否则 null。实测子集另列比率和覆盖率，结算分母比率另列 `settled_cache_hit_bp`；汇总后求比率，不平均百分比。 |
| 缓存写入 | 只有整个统计范围的数据完整时才返回总量；未上报和明确上报 0 必须区分。单请求含多次产出时也必须全部上报才算完整。 |
| 输出速度 `tokens_per_1k_sec` / `avg_output_tps_milli` | 同批明确 Token 单位且已测耗时请求的输出 / 毫秒总和 × 1,000,000；字符不参与速度分母，仍参与总耗时。除以 1,000 得 Token/s；总耗时为 0、无样本、请求历史或单位覆盖不足时返回 null，子集另列速度/覆盖。包含等待与 Realtime 会话停顿，不是纯解码速度。 |
| 平均总耗时 | 已采集耗时总和 / 有效样本数，向下取整为整数毫秒；包括失败及非流式请求，明确 0ms 有效。未采集不当成 0。 |
| 平均 TTFT | 流式且已采集的首字毫秒总和 / 有效样本数，整数毫秒向下取整；明确 0ms 有效，非流式排除。无样本或历史覆盖不完整返回 `null`。 |
| TTFT 分位数 | 只收流式且已采集的样本，保留明确测得的 0ms；未采集不参与。历史覆盖不足或没有有效样本时返回 `null`，附样本数与历史覆盖字段。 |
| 门户平均 RPM / TPM | 日历范围总请求 / 总 Token ÷（天数 × 1,440）；返回值放大一百万倍。今天尚未结束时也按完整日历窗口，分母由 `avg_rate_window_minutes` 返回。 |
| 门户 `live.tpm` | 限流器当前自然分钟内准入预估的 Token；`rate_basis=admission_estimate`。它用来对照限流上限，不等于已结算实际用量。 |
| 管理日志 `rpm` / `tpm` | 最近 60 秒窗口。无维度过滤读取 Redis 结算 KPI；带过滤读取 CH，存在异步入库延迟，响应注明 `rate_source`。 |
| Realtime 请求数 | 当前账单与统计按会话计一笔；Token 是会话内每个唯一 `response.done` 的用量之和。相邻轮次重复使用上下文仍产生输入用量，重复发送同一个 Response ID 则不重复计数。 |

所有放大后的比率先用 i128 计算，再限制最终 i64 返回值。不能先对 i64 分子做饱和乘法，否则在大数据量下会把结果算低。

## 本次发现与修正

- Realtime 原先只取输入、输出、缓存三个总数，丢弃音频/图片细分与缓存采集状态。现保留这些字段，扣除缓存与模态的交集，缓存图片/音频使用独立价轴。
- 按 Response ID 去重；结构错误、负数、小数、总量冲突、无法确定的混合模态缓存和累加溢出不修改已验证用量。网关发送错误并关闭，按已验证部分收尾，不用错误用量覆盖前面的计数。
- 分图片流式累加的完整性标记由 OR 改为 AND；Realtime 多轮也采用相同规则。部分采集的正缓存数仍可保存，但不能被宣称为完整统计。
- PostgreSQL 门户账单优先使用显式采集标记，不再用“缓存数大于零”覆盖明确的 `false`。只有缺少历史标记时才保留正缓存数的兼容判断；账单 API 也补出图片输出及缓存模态交叉明细。
- PostgreSQL 计数列仍为有符号 32 位。超过可表示范围现在原子拒绝结算；此前会单独截断 PG 计数，而 JSON/outbox 保留原数，造成跨库不一致。正常计数上界可完整往返。不扩大现有计价公式，也不把异常值压成合法账单。
- TPS、TPM、命中率及占比改用加宽后的整数中间值，保留负向环比语义；管理分析无 TTFT 样本时返回 `null`。

Realtime 字段与交叉关系核对 [OpenAI 官方用量示例](https://developers.openai.com/api/docs/guides/voice-latency-cost#example)。本地测试还覆盖音频/图片缓存混合、独立价格、重放与部分采集；兼容扩展字段不等于供应商均保证上报。

额外修正了 CH HTTP 标量参数转义：反斜杠、换行、制表符等先按 escaped 格式编码，再进行 URL 编码，调用方传原始字符串。否则特殊模型名会查询失败，字面量 `\t` 等还可能被改写成控制字符。实现依据 [ClickHouse 官方 HTTP 参数规则](https://clickhouse.com/docs/interfaces/http#tabs-in-url-parameters)，并用实际 24.8 服务往返测试中文、控制字符、字面量转义、SQL 片段和 URL 特殊字符；这些都必须按数据保真。此修复作用于统计、日志与管理分析共用客户端。

- `tests/support/image_streaming_cache.rs`：分图片累计的部分缓存采集，两种产出顺序均不误报完整。

## 已知边界与后续核对

- Chat/Responses/Gemini 已统一当前支持的模态与缓存交叉采集，并解析 Gemini 模态数组；Anthropic 原生及转换的严格解析也已补齐。文本请求的单笔用量来源及部分计数保存已在后续 [来源阶段](token-usage-provenance.md) 接入。聚合来源覆盖已在后续阶段补齐；仍需核对媒体专用路径、真实供应商账单、Anthropic 两种缓存写入 TTL 的分别存储与定价、独立工具费用，不能据此宣称所有供应商正确。
- CH 当前聚合提供总输入、缓存、输出、推理；音频/图片与缓存交叉明细保存在 PG 用量和计价快照，尚未提供独立长期分析列。
- Realtime 此处核对的是对话 Response 用量；独立输入转写事件使用另一个模型和价表，尚未纳入该会话计费，不能将会话统计视为供应商所有音频服务费用的合计。
- 历史未采集的用量细分无法凭空修复，严格覆盖率可能使部分范围指标返回空值。
- 前端尚未适配新增 TTFT 覆盖字段和可空类型；渠道时间线现有 `Math.max` 合桶会把 `null` 转成 0，并且分桶分位数不能通过取最大值准确合并。本轮仅修改后端，不能把接口验证当作页面已正确展示。
- 平均 TTFT 已改用有效样本独立聚合并接入限定范围的历史恢复，另见 [平均首字核对](ttft-average-accounting.md)。均值及分位数的历史恢复尚未验证大规模性能，持续写入时可能短暂返回覆盖不完整；不能将小规模功能验证推广为性能验收。
- 单机 outbox 批次成员变化后的重投去重边界、真实供应商联调、缺失上游 usage 的估算偏差仍需继续验证。平均总耗时及输出速度的同批样本口径已在后续阶段修正，见 [总耗时核对](latency-statistics-audit.md)；前端显示及大规模查询性能仍需单独验收。
