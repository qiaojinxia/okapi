# Token 输出速度单位核对

日期：2026-09-30。本轮实现与固定源码的完整关联回归已完成。平均总耗时保留全部有效测时请求；Token 输出速度仅使用明确 Token 单位、已测耗时的配对请求。没有改动前端、历史财务金额或生产服务。

## 基线与新口径

实际 HTTP 基线 `/tmp/okapi-output-rate-baseline.log` 退出 **101**：两笔请求的费用 2,000 micro、输出 200、平均耗时 5,000ms 均正确，但输出速度返回 20,000 milli（20 Token/s）。独立预期是 Token 输出 200 / 1,000ms = 200 Token/s，另一笔 TTS 的 11 字符 / 9,000ms 不参与 Token 分母。基线前后 1,170 个后端/构建文件指纹一致，报告 `...-baseline-report.json` 保留原断言。

新的 `tokens_per_1k_sec` 与 `avg_output_tps_milli` 是输出 Token 小计 / 同批 Token 请求的毫秒小计 × 1,000,000，除以 1,000 得 Token/s；先加总，再求比率，不平均各笔或各模型速度。结算 Token 可包含估算；整个请求耗时包含等待与会话停顿，这不是纯解码速度或供应商实报速度。

| 场景 | 速度与覆盖 |
| --- | --- |
| 全部明确 Token/字符单位、存在正耗时 Token 样本 | 返回配对 Token 样本速度，字符仍参与平均总耗时及分位数 |
| 明确 Token 输出零、正耗时 | 速度为 0，保留有效样本 |
| 全部字符、无有效 Token 测时样本或 Token 耗时小计为零 | 速度为 null；已测得 0ms 仍计样本，不凭空造速度 |
| 请求历史或单位识别不足 | 全范围速度为 null；`observed_output_tps_milli` 单列有效配对子集 |
| 测时缺失 | 输出与耗时都不计入速度配对，样本覆盖以明确 Token 请求为分母 |

`output_tps_history_*` 表示请求覆盖，`output_tps_unit_coverage_bp/unit_complete` 表示单位覆盖，二者独立。历史齐全但单位未知时不能返回全范围速度。额外返回明确 Token 请求数、有效样本数、耗时/输出小计、未知单位请求数和样本覆盖；无样本与明确零分开。这六项计数/小计均来自同一个选中的速度数据源；单位覆盖分母是全范围请求，样本覆盖分母是该来源中明确 Token 请求。历史缺口也计入该指标无法识别单位的请求，不能把子集样本覆盖 100% 当成全历史采集完整。兼容字段 `performance_completion_tokens` 现在表示这批明确 Token 测时样本的输出，不再从总耗时分母倒推速度。

## 存储与接口

独立 `mv_output_rate_5min` 用完整分析维度保存 `requests`、`known_units`、`token_requests`、`samples`、`total_ms`、`output_tokens`，均为条件/计数聚合状态，无 raw TTL、无 POPULATE。重复 schema 和相同批次重放不增加请求或样本。旧耗时 MV 和主 Token/费用聚合保持原语义。

读取按粒度核对基础请求与新聚合覆盖；完整时用 MV，缺口只在限定范围内扫描 raw 并择一使用完整度更好的来源，重叠数据不相加。高于基础请求数的来源无效；旧维度残差仅在整体和已拆分部分覆盖完整、各差值非负时派生。七种观察聚合分别核对，不用来源覆盖替代单位或测时覆盖。

管理趋势、拆分、堆叠、实体行内用量、模型/渠道/时间线，个人图表、按日统计、活动以及 CH 管理日志/PG 个人日志汇总已接入。PG 配对排除 pending，纳入已测得耗时的 settled/refunded/failed；原消费/退款金额仍按各自状态汇总，不用统计速度改账。

- 混合 Token、字符、未知和矛盾元数据；有效输出零、0ms、缺失耗时、失败样本、特殊模型名、主体/端点/node 过滤、Top N 其他分组加权，以及 PG pending/refunded/failed 与用户/当前密钥范围。费用、请求、主 Token 和平均总耗时分别使用固定预期。明细清空后重测保留聚合。

## 仍需核对

旧 TTS 字符曾混入主 Token 总量，本轮没有重写这段历史，也不猜模型名/费率来分类。只读检查还确认前端渠道时间线的小时合桶仍对速度取最大值，模型/渠道卡片的旧 number 格式化也可能将 null 除成零；界面尚未消费新的速度配对与覆盖字段。本阶段没有改动或运行前端，这部分不能算作界面统计已验收。独立 TTL/工具费用、Realtime 输入转写、估算偏差、真实供应商账单、持续写入和大规模查询性能仍需继续验证。新 MV 需先由 worker 完成幂等 schema 初始化，再由控制台读取；本轮只操作隔离测试服务，没有部署或重启共享开发/生产服务。
