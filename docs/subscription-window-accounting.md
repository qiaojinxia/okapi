# 普通请求的订阅周期归属

状态：本阶段生产代码完整后端回归已通过；普通预扣与长期冻结混合资金专项随后通过。执行结果以 [核心验证记录](core-api-verification.md) 为准。

一笔普通请求使用准入时的订阅周期。它在旧周期发起，在新周期、取消订阅后或换套餐后结束，都不能把旧周期的未用额度转入当前周期。钱包仍按原有预扣与实际费用结算。

## 凭据与账单

带周期的 Redis 普通预扣使用 `金额|到期毫秒|密钥ID|1|w:周期身份`。周期身份由订阅实例 ID 和窗口起点微秒组成。网关保留它直至请求结束，超时清理删除 Redis 凭据后，迟到的实际结算仍使用同一身份。

迁移 `0024_billing_source_window.sql` 在 `billing_records`、`billing_record_receipts`、`billing_sync` 增加 nullable `source_window`。详细账单归档必须原样保留身份；重复结算同时核对金额、用户、密钥、支付池及周期。Chat/Responses、Embeddings/Rerank、音频、图片、视频、自定义透传和 Realtime 的成功账单传递准入身份。长期图片冻结沿用其已有 `balance_holds.source_window`。

NULL 代表钱包或历史未采集的周期，不能伪造历史快照。2–4 段旧 Redis 凭据仍可关闭；无法证明周期的旧订阅预扣尚未关闭时，现代订阅切窗/取消返回待恢复错误，不能一边接受新周期一边猜测其归属。没有凭据、也从未记录周期的历史账单，仍保留原支付池退款的有限兼容，无法重建未保存的历史周期。这不是历史数据已补齐的证明。

## 滚窗、取消与迟到结算

滚窗或取消时，普通请求的旧预扣不再被带入新周期的 PG 配额目标。长期图片冻结继续保留其既有资金，不混用两种冻结规则。

Redis 关闭旧周期普通凭据时，释放凭据和并发槽，对当前订阅余额的变动为零。关闭同周期凭据时仍按预扣减实际金额多退少补。退款结果另带 `closed`，使超时 worker 能区分“真实关闭但当前周期入账为零”和“凭据已不存在”。

旧周期成功请求仍生成完整实际账单、用量及 outbox。其 `commit=-实际金额` 与一笔 `sub_expire=+实际金额` 在同一 PG 事务提交：后者修订此前已经过期的旧额度，避免再从新周期扣钱；不是新增充值。两条事件合计不改变新周期额度，消费账单仍保留真实金额。失败与无费用退款没有实际消费，不需要这笔修订。

普通异步图片结果使用同一个用户锁与结算事务，把结果、账单、周期修订和 Redis 待恢复意图一起提交。Redis 暂时不可用时不能抹掉已接受的实际账单。

## 退款与修复

管理员退款继续冲销原账单四金额和密钥已用额。只有原周期仍可用时，才产生可用订阅额度；周期已被替换、取消，或截止时间已过时，退款事件与相反的过期事件同事务记录，可用入账为零。接口保留 `refunded_micro` 表示账单冲销额，并增加 `credited_micro` 表示此次入账额度。重复退款不再记账。历史凭证走同一规则。

对账与余额修复只把当前周期的普通预扣计入当前在途金额；其他周期的普通凭据仍保留以释放并发或供审计。周期身份在时间到期后、正式维护前保持不变，准入另外检查截止时间，避免一次余额修复把“尚未滚窗”误判为“已经换了周期”。

旧格式、低层 `sub_set` 的无周期兼容接口不具备完整周期事实；在线业务通过 PG 订阅流程维护周期。不同版本结算写入者混跑、缺失历史周期数据及人工越过这些流程改账，都不能由本次专项结果推断为已验证安全。
