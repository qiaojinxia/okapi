# 系统设置：AI 接入

入口：管理后台 → 系统设置 → AI 接入。前端沿用已有 `POST /mcp` 与设置接口，无数据库迁移，不自动开启写入、不生成凭证、不开放公网。

## 接入流程

1. 在支持 HTTP MCP 的可信客户端中添加服务。页面按当前浏览器 origin 生成 `/mcp` 地址，提供 JSON 配置模板及地址复制。
2. 模板使用 `Bearer <OKAPI_API_KEY>` 占位符，不读取或导出当前登录密钥。由用户在客户端中替换为专用账号凭证；具体配置格式须与客户端匹配。
3. 点击测试连接：使用当前登录凭证，向同源 `/mcp` 发送 `initialize`、`tools/list`。仅检查握手和工具发现，不执行 `tools/call`，不调用真实模型。结果展示本次服务信息与账号可见工具。
4. 选择巡检、用量分析或管理变更模板并复制提示词。提示词不含凭证，也不自动安装客户端、建立连接或授权。

## 权限与边界

- 通过已脱敏的 `GET /admin/settings` 读取 `mcp_write_enabled`，因此 `settings.read` 用户可看状态；不要用要求写权限的单项设置接口。
- 未配置该值时按现有后端语义显示只读；读取失败或格式异常时显示未知状态，不允许覆盖为默认值。
- 仅 `settings.write` 用户能切换全站写入，开启/关闭均须确认，再提交现有设置接口。保存成功刷新列表和单项缓存；保存失败保持原状态。
- 页面不改变现有 RBAC。MCP 写工具仍要求全站开关、`mcp.write` 及对应资源权限。超级管理员下的新密钥仍继承管理员权限，模型限制及调用额度不是 MCP 工具隔离。
- 现有工具的 `confirm` 参数由客户端提供，不是后端人工审批。本次只增加全站开关的 UI 确认，不实现逐笔审批。敏感操作应保持只读或在可信客户端启用审批。
- 测试固定使用同源路径、禁止跟随重定向，10 秒超时。HTML 回退页、非法 JSON-RPC、错误 ID、无效工具列表和鉴权失败都不会显示连接成功。
- 此诊断不是完整客户端兼容性认证；也不证明外部客户端已连通。不同账号的工具集可能不同。
- 云端 AI 无法直接访问用户电脑的 localhost。远程接入需配置可达的 HTTPS 地址、认证与访问控制，本页面不会创建隧道或暴露端口。

## 回归验证

`frontend/e2e/mcp-settings.spec.ts` 使用隔离接口桩覆盖配置/提示词复制不泄露登录凭证、只读默认值、真实工具发现、错误与重试、全站开关确认、权限不足、加载失败和中英文桌面布局，不修改本地业务库。
