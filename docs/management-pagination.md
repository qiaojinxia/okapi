# 管理资源列表分页

2026-09-27 起，下列后端列表统一默认每页 **20 条**，分页在数据库查询中执行。响应保持 `{ "data": [...], "total": 205 }`；`total` 是权限和筛选范围内的总条数，不是当前页长度。

## 参数和边界

- `limit` 省略时为 20；显式数值夹到 1～200。0 或负数按 1，超过 200 按 200。
- `offset` 从 0 开始，省略或负数按 0。只传 `offset` 仍保持每页 20 条。
- 搜索、状态、用户/批次和权限过滤先于分页，总数遵守相同过滤条件。
- 超过末页返回空 `data` 和真实 `total`。非法整数、非法 UUID 等查询参数返回 400 `bad_request`，不返回 HTML 或纯文本错误。
- 不存在用于绕过上限的“全量模式”。内部价簿编译和配置加载仍可直接使用 store 的 `Slice::ALL`，不通过 HTTP 列表获取完整配置。

例如共 205 条：省略参数返回第 1～20 条；`?offset=20` 返回第 21～40 条；`?offset=200` 返回最后 5 条；`?offset=220` 返回空页，各页 `total` 都是 205。

## 调用方迁移

此前配置类列表无 `limit` 时返回全量，用户/管理密钥/兑换码缺省为 50。需要查一个模型或渠道时优先使用 `q`；需要完整选择项或核对删除结果时，按 `total` 逐页读取，不能把第一页当成全量，也不能用一个超大 `limit` 代替翻页。

分页期间没有写入时，稳定排序保证相邻页不重不漏。不同 HTTP 请求不共享快照，并发插入/删除可能移动 offset；本接口不是一致快照导出。数据和计数查询也不承诺同一个事务快照。

本次修改后端和后端测试，未修改、构建或验收前端；现有全量读取的选择器调用方仍需适配，部署前应完成相应兼容验证。其他使用独立游标/limit 类型的日志、审计、死信和门户账本接口不属于本次 12 类资源契约，不能据此声称所有列表都已统一。公开模型目录使用独立的默认 20 / 最大 100 契约，见 [模型目录](model-catalog.md)。

## 验证

`list_pagination` 使用每类至少 205 条的夹具，使缺省页宽和 200 上限在新数据库中也能被验证。逐接口比较独立 SQL 总数、默认/offset-only/负 offset、超大和非正 limit、末页、权限范围、搜索和用户过滤，并比较两页拼接与一次读取的内容。兑换码有独立 205 条批次，验证 20 条默认值、逐页完整性、状态筛选和凭证不泄露。具体执行结果见 [核心验证记录](core-api-verification.md)。
