# 聚合 Token 来源与缓存命中率核对

2026-09-29。本阶段关注管理看板、个人统计、管理日志及 PG 个人账单的后端统计口径。本地关联、日历边界及核心包回归已通过，并行更新的 Anthropic 模块也已按最新文件另复测通过；此前 1,191 项完整回归属于单笔来源阶段，不能代替本阶段结果。

结算输入与输出保持原有总量；缓存读取、缓存写入、推理和模态是内部拆分，不额外加入总 Token。`token_usage_basis=settled` 明确说明总量可能包含估算或本地复核。输入、输出分别返回实报、估算、本地复核和未知的请求数、结算 Token 数、请求占比和 Token 占比。请求占比与 Token 占比使用不同分母，不能混用。

| 字段 | 分母与返回条件 |
| --- | --- |
| `cache_hit_bp` | 同范围全部请求均有原始上游输入、原数与结算输入一致且明确上报缓存读取，使用这些请求的缓存读取 / 输入总量。输入总量为零返回 null。 |
| `measured_cache_hit_bp` | 仅使用上述条件成立的请求，先加总分子与分母再求比率；没有有效分母返回 null。 |
| `measured_cache_hit_requests` / `measured_cache_hit_coverage_bp` | 实测配对请求数及其占整个范围请求数的比例；覆盖不足不能将子集命中率解释为全范围命中率。 |
| `settled_cache_hit_bp` | 保留此前的结算输入分母口径，要求缓存采集完整。该比率不代表输入一定由供应商实测。 |
| `token_provenance.history_coverage_bp` | 有来源记录的请求 / 原统计范围请求。旧记录的来源仍可能为 unknown，数据存在不等于上游已实报。 |

新增 `mv_usage_sources_5min` 独立保存可加的计数与总量，不使用 POPULATE，不重写旧 Token 或金额视图。每个粒度从新聚合与保留的 raw 中选择一份，不能叠加。来源记录缺失或重复数超过原聚合时，不制造完整覆盖；无法还原的历史归 unknown。旧总量视图没有输入、输出独立轴且来源未完整覆盖时，未知轴 Token 为 null，不凭总量猜分配。

趋势、模型堆叠、供应商/用户折叠和流向先加总计数，再计算比率；不得平均百分比。查询保持原时间和实体过滤，特殊模型名通过 CH 类型参数绑定。
