# 平均首字时间核对

2026-09-28。继分位数专项之后，检查管理趋势、拆分、堆叠与个人用量、活动数据的平均首字时间。本阶段不修改 Token 计数、价格或余额公式。

旧 `mv_cube_hour` / `mv_analysis_hour` 使用所有 `ttft_ms` 的和，却仅以正值个数作分母，没有排除非流式请求，也不能把明确测得的 0ms 当成样本。相同数据在均值与分位数接口中因此会出现不同口径。

新增 `mv_ttft_reporting_hour` 保留与分析立方体相同的维度，记录请求覆盖数、有效 TTFT 和及有效样本数。有效条件与分位数共用：流式请求，且明确上报 TTFT；旧行没有采集标记时仅接受正值。均值为有效毫秒总和除以有效样本数，向下取整为整数毫秒；明确零保留，无有效样本返回 null。不能平均各模型、渠道或时间桶的平均数。

升级不删除旧聚合，也不通过 POPULATE 回填。按所查询的时间和用户范围核对新聚合覆盖；缺口粒度从仍保留的 raw 明细恢复，必须择一使用整份数据，不能相加。raw 也不全时，只公开可用的样本数、和及覆盖信息，完整区间均值返回 null。旧立方体剩余记录只有在整体与已拆分部分都完整时才允许相减恢复 TTFT；金额、请求、Token 仍保留全部原统计。

`ttft_observed_requests`、`ttft_history_coverage_bp`、`ttft_history_complete` 描述历史数据覆盖，不表示所有请求都测得首字时间。非流式或没有输出的请求仍计入总请求数，但不进入 TTFT 分母。已测得首字后再失败的请求保留该有效样本，待结算的 PG 账单不参与；PG 汇总也使用向下取整。聚合覆盖数领先于原始请求总量时不能被当成完整数据，也不能和另一缺口粒度相抵。

隔离 HTTP 与 ClickHouse 集成验证覆盖：0ms、缺失值、非流式、显式未采集的正数、跨模型及供应商加权、其他用户隔离、raw 留存删除后新聚合可用、旧数据恢复及覆盖不足、重复插入去重、重复 schema 初始化。个人 PG 日志汇总也改为同一整数取整方式，并将已有首字样本的失败请求纳入统计，待结算请求仍不参与。前端可空指标适配与大规模历史恢复性能仍需另行核对。


首次专项因 ClickHouse 24.8 要求连接中的子查询必须有别名而返回 500，实际退出 101、2 failed（`/tmp/okapi-ttft-average-targeted-1.log`）。修正查询后，初始 2 项专项实际退出 0、2 passed、11 filtered（`/tmp/okapi-ttft-average-targeted-2.log`）。后续增加无分析维度旧库、统计覆盖领先、PG 失败样本与取整用例；这些断言均在下述完整统计套件中通过。

另修复堆叠趋势折入“其他”时未累加缓存读取采集数的问题，避免完整上报的缓存命中率在堆叠视图变成 null。与 TTFT 样本聚合一起验证，未改缓存或 Token 计价。
